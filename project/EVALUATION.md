> **The data in this report is synthetic.** It is generated by
> `scripts/evaluate.ts`, not measured at KMITL. The numbers describe how the
> detectors behave on that generator, and nothing more. Regenerate with
> `npm run evaluate`.

## Settings used

L1 threshold 7 A · L3 alpha 0.3, k 6, minSamples 5, sdFloor 0.05

`k` was chosen by sweeping it on this generator and checking the choice holds
across several seeds, not by taste. Reproduce either with:

```bash
for k in 3 3.5 4 4.5 5 6 8; do EVAL_K=$k npm run evaluate; done
for s in 42 7 99 2026; do EVAL_SEED=$s npm run evaluate; done
```

## Reading this

L1 is a fixed 7 A threshold, so its recall on `subtle_waste` is 0 by
construction — that class is generated below the threshold on purpose. L2 and L3
compare a reading against the room's own behaviour instead, which is the only way
that class can be caught. Any gain comes with false positives; the FP column is the price.

Without L4, describe the system as *rule-based + statistical anomaly detection*.
It is not machine learning.
